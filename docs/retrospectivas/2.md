# Retrospectiva da Iteração 2

- **Data:** 08/10/2026 · **Grupo:** Vitor Arthur Keller e Lucas Camilo Moraes

## O que decidimos nesta iteração
- Registrar a migração SQLite → PostgreSQL como ADR formal (`docs/adr/0001-migracao-postgresql.md`), com alternativas, consequências e um critério de validação objetivo, em vez de deixar essa decisão implícita só no README.
- Escolher contêiner Docker, não instalação local nem serviço gerenciado, como forma de subir o PostgreSQL, para manter paridade entre as duas máquinas do grupo e o CI.
- Declarar, em vez de corrigir silenciosamente, a divergência encontrada entre o diagrama de dados e o schema real (coluna `aceita_em` ausente em `src/db.js`), deixá-la para ser corrigida junto da própria migração, não antes.

## O que funcionou
- A proteção da branch `main`, configurada na iteração anterior, já forçou esta entrega inteira a passar por Pull Request e CI antes do merge, a prática se sustentou sendo usada de verdade, não só configurada e esquecida.
- Reaproveitar os riscos e critérios de aceite já escritos no `docs/analise.md` deu rastreabilidade real ao ADR, em vez de justificativas genéricas tipo "Postgres é melhor".

## O que mudaríamos
- O diagrama de dados em `docs/projeto.md` foi publicado antes de alguém comparar campo a campo com `src/db.js`, por isso a divergência do `aceita_em` só apareceu agora, numa revisão de ADR, e não quando o diagrama foi criado.
